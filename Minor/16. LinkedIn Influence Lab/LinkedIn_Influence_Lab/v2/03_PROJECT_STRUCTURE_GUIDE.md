## 2. What each item is for

| Path | Purpose |
|---|---|
| `app.py` | Streamlit entry point: theme, sidebar navigation, page routing. Start here when the UI looks wrong. |
| `HOW_TO_RUN.txt` | Plain-text start-up guide (Windows, macOS, Linux). |
| `README.md` | One-page project overview for clients and reviewers. |
| `requirements.txt` | Python packages the app needs (pip install -r requirements.txt). |
| `run_app.bat` | Windows launcher: creates a virtual environment, installs packages, starts the app. |
| `run_app.sh` | macOS/Linux launcher (same steps as run_app.bat). |
| `.streamlit/` | Streamlit theme and server settings (config.toml). |
| `src/lil/` | All application code. One module per responsibility (see below). |
| `src/lil/paths.py` | Every folder path and the phase/deliverable catalogue. Change locations here only. |
| `src/lil/store.py` | JSON read/write, the log file, and the phase-status ledger. |
| `src/lil/settings.py` | User profile (inputs) and plugin configuration load/save. |
| `src/lil/knowledge.py` | Content brain: personas, pillars, idea bank, post building blocks, prompt templates A-C. |
| `src/lil/context.py` | Turns the profile into placeholders; computes effective pillar weights. |
| `src/lil/planner.py` | Builds the 6-week slot plan (dates, pillar, format) with a weighted rotation. |
| `src/lil/ideation.py` | Generates 15+ ideas (Template A) via AI plugin or template engine. |
| `src/lil/drafting.py` | Creates drafts, regenerates one draft, Template B rewrite, Template C article summary. |
| `src/lil/quality.py` | Quality, inclusivity and source-attribution checks that score each draft. |
| `src/lil/audit.py` | Profile audit/checklist score, headline and About rewrites, content pillars. |
| `src/lil/personas.py` | Side-by-side comparison of the three user-story paths. |
| `src/lil/calendar_builder.py` | Merges slots and drafts into the calendar and writes the Excel/CSV files. |
| `src/lil/analytics.py` | Engagement logging, CSV import, metrics, insights, scorecard, strategy refinement. |
| `src/lil/charts.py` | Matplotlib charts and the workflow diagram. |
| `src/lil/docx_kit.py` | Word styling helpers (colours, tables, callouts). |
| `src/lil/reports.py` | Builds every Word/Excel deliverable. |
| `src/lil/backup.py` | Zip backup per phase, full snapshot, safe restore. |
| `src/lil/pipeline.py` | Runs phases 1-5 and the deliverable build; the automated flow. |
| `src/lil/llm.py` | Calls the active AI plugin and falls back safely if anything fails. |
| `src/lil/trace.py` | Maps the 24 parts of the project brief to the code that implements them. |
| `src/lil/auth.py` | Admin passcode (salted PBKDF2). Gates the Folder map; not a substitute for file permissions. |
| `src/lil/guidance.py` | Field guide (type, rule, example, why) and the validation rules for the Inputs page. |
| `src/lil/phase_spec.py` | What each phase does, needs, depends on and hands on (shown on the Command Center). |
| `src/lil/persona_content.py` | Per-path tabs, weekly KPIs, benefits/setbacks and phase-by-phase effects. |
| `src/lil/hubs.py` | Logic for the three path hubs (consistency, recruiter, authority) and the weekly path KPIs. |
| `src/lil/samples.py` | Builds the complete fictional sample workspace for each path. |
| `src/lil/exports.py` | In-memory ZIP downloads: one deliverable set, or all sets. |
| `src/lil/compat.py` | Adapts to Streamlit's width='stretch' / use_container_width naming. |
| `src/lil/theme.py` | Colours, CSS and small UI building blocks. |
| `src/lil/plugins/` | Drop-in plugins: AI providers, export targets, import mappers. |
| `src/lil/ui/` | One file per Streamlit page. |
| `docs/` | Requirements, architecture, folder guide, beginner guide, traceability, FAQ. |
| `templates/` | Prompt templates A-C, profile checklist, and a sample engagement sheet (appendices). |
| `sample_data/` | Handpicked fictional data for every step and path: profiles, engagement exports, KPIs, hub data, a job description and an article. |
| `sample_workspace/` | The sample workspace (created on first launch): same layout as your own workspace, but fictional and kept separate. |

## 4. Debugging cheat-sheet

1. Read `logs/lil.log` (AI fallbacks, backups, failures).
2. Check `data/state/status.json` for the phase states and notes.
3. Open the phase's JSON in `phases/`: these are the inputs to the next step.
4. Reproduce in isolation: `LIL_HOME=/tmp/x python -m pytest tests -k name`.
5. To add a feature: content in `knowledge.py`, logic in an engine module, orchestration in `pipeline.py`, page in `ui/`, test in `tests/`.
6. Secrets live only in `data/inputs/plugins.json`; never commit or share that file.
